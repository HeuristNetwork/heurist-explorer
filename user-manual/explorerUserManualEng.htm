Heurist Explorer

Explorer is the module that allows filtering, analysing, visualising and publishing data in your database. You define query sources (what to show), look at them in independent presentation modules (how to show it), and publish the result as a standalone page or a website.

1. Filter builder and source editor

Search on the toolbar opens the Query Source editor. It defines a query source: the query and the settings the presentation modules use with it. It can sit on the left (Vertical) or above the modules (Horizontal); choose with the … button.

Inline query helper

Type a query in the query box. The helper suggests record types, fields and operators as you type, and shows the query as a sentence below the box. Press Enter or Filter to run it.

Filter Builder

Builder opens the Filter Builder, where a query is put together from conditions without typing the query language.

Parameterized filter and Filter Form

A condition can be a parameter instead of a fixed value. A query with parameters is shown as a Filter Form: the user fills in the values (text, dates, lists, facets) and runs the search. This replaces the former faceted search.

Geographic, time and column fields

More (in the … menu) shows the presentation settings: which fields Map uses for geometry and Timeline for dates (also through linked records, when the records have none of their own), and which columns Data shows.

Expansion rules

Rules that add linked and related records to the result, level by level. Graph uses them to expand the network; Data can show each level.

Save stores the query with its settings as a Query Source; Add puts a saved source into your Workspace.

2. Saved filters and sources on the toolbar

Filters, Entities (record types) and Sources list what can be opened in the Query Source editor.

Favorites

Star a filter, record type or source to keep it in Favorites.

Workspace

A saved working set of query sources you are working with now.

Subsets

Restrict further searches to a subset of records.

3. Presentation modules

Each module is an independent application that shows the current result and selection; selecting records in one module highlights them in the others. Each can also be published on its own.

  • Data: the result as a list, table or cards.
  • Map: records with geographic data, in layers.
  • Graph: records and their links and relationships as a network.
  • Timeline: records with dates, in bands.
  • Record view: the full content of the selected record.

Modules have their own manuals, opened with the help button in the module.

Layout configuration

The Options menu (the gear button on the toolbar) opens Configuration, Base style settings, Help, Getting started, the management tools (tags, registered files, users, groups, publication, websites) and the Query tracer.

Explorer configuration (Options > Configuration) sets the toolbar position and button size, and which pane each module occupies. Several modules in one pane work as tabs: one is visible at a time. The tools (Report, Crosstabs, Actions, Export, Publish) are placed in panes like the other modules; by default they are in the center pane after Graph. Modules dragged to Unused are not shown at all (Result always has a pane).

Toolbar position In panes puts the buttons next to what they act on. The search buttons (Filters, Entities, Sources, Favorites, History, Workspace) are a row of small buttons at the top of the left pane; the search editor is always shown there, and the « button folds the left pane to a narrow strip (» opens it again). The gear button at the end of that row opens the same Options menu. There is no toolbar on the right: modules and tools are shown with tabs at the top of their pane (only icons when the pane is too narrow for the names), and the small arrows on the dividers between panes fold a pane, bring it back, or enlarge it to take the whole width (or height); a folded pane shows the icons of its modules.

Base style settings

Options > Base style settings sets the colours, fonts and sizes of Explorer and its modules, as the Base settings of a website do. Choose a theme to fill the colours, then change single values; empty values use the Heurist defaults. The font size is the normal text size (12px by default); the larger and smaller texts follow it. The heading font and colour apply to all headings. The preview shows the result before you apply it; Explorer reloads when you apply the changes. The settings are kept in this browser, for each database.

4. Tools

Reports, Crosstabs, Actions, Export, Publish. Each tool is shown in its pane like a module (Explorer configuration, Layout) and follows the current result and selection.

Export

Export (a toolbar button or pane tab) writes the records of the current data source into a file. The file is made on the server; when it is ready, a link downloads it. Only you can download it, and it is kept for 24 hours. You can switch to another module or reload the page: a running export continues and is shown again when you open Export. Stop ends it. Export results lists your finished exports: download them, open them in a new tab, or mark them and remove them. A new export is refused while your export results take more than 100 MB.

  • Scope: the current result, the selected records, or one record type of the result. The tool follows the current data source and selection.
  • Format: XML (HML, can be imported into another Heurist database; the default), JSON, CSV or TSV (one table per record type; several tables are packed in a zip), GeoJSON, KML or Gephi (GEXF, at most 10,000 records).
  • Columns (CSV, TSV, GeoJSON, KML, Gephi): for each record type choose Minimal (ID, record type, title), Metadata (also URL, dates, owner, visibility), All (also every field) or Custom (pick and drag the fields). Use data source settings adds the column, geographic and time fields of the data source. In CSV the first column is always H-ID, the record ID.
  • Expansion rules (XML, JSON, Gephi): also export linked records - through any link of a kind up to 4 levels, through the rules of the data source, or through custom rules for this export only. Each record is written once.
  • Value formats (formats with columns): temporals raw or human readable; files as URL, full information or ID; titles of pointed records; terms with their hierarchy. XML and JSON write the values as stored.
  • Additional properties: CSV options (separator, quote, separator of repeated values, header row, line ends); for XML and JSON, Include human-readable names and local IDs for everything - without it record types, fields and terms are identified by concept codes only.
  • Output: a record limit (All, 50 ... 500K) and the file name.

The number of records in one export is limited by the database setting (100,000 by default, expanded records included).

Story map

A story map tells the story of a record, the story topic (a person, an expedition), with the records that describe it in time and on the map, the story elements (the life events of the person, the campsites of the expedition). The story is shown in the tool pane; the current element is shown on the Map. A story map is saved as a record (Presentation set) and can be placed on a website page.

  • Toolbar: New story; the list of story maps; Story editor shows or hides the configuration; the pen edits the record (name, owner, visibility); Save; Delete (refused while website pages use the story map); Run shows the story topics as the result and the story of the first one. Select another record of the result to see its story.
  • Source: the query of the story topics; the story elements, found by an expansion rule from the topic (all of one record type); their order (a date, as found, or by hand for each story); the start and end info (a text or a template run on the topic); the most elements read.
  • Presentation: the template of an element; Vertical, Horizontal, Carousel (one element with Previous / Next) or Tabs; where the start and end info is shown; the texts shown before a topic is selected and when a topic has no story.
  • Mapping: the background map document; the places of an element (begin or main, transition, end: geographic fields of the element or of linked records); a line between them; all places of the story kept on the map; the duration of the move to the next element; the symbology of the places and of the line.

Most changes are shown at once. A new query, rule or background map is applied with Apply. Changes are kept only after Save.

Crosstabs

Crosstabs count records by the values of one, two or three fields: rows, columns and pages (one table per page, chosen above the table; All values shows one table of all pages). Instead of counting they can show the sum, average, minimum or maximum of a numeric field (the first value of each record). A record with several values of a field is counted once for each value; the totals count each record once, so they can be smaller than the sum of the cells. A crosstab is saved as a record (Presentation set) for one record type: only records of that type are counted. It can be placed on a website page.

The Crosstabs pane shows crosstabs; it changes nothing in them.

  • Crosstab list: with the source Current result, the crosstabs for the record types of the result come first (with the number of records); the others are listed below and can not be chosen. When only one crosstab fits the result, it is shown at once.
  • Source: Current result — the records of Explorer's result of that record type; or Own query — the query of the crosstab. A value of the query (a parameter) is asked above the crosstab; the parameter $SELECTED$ takes the selected records.
  • Edit and New open the designer; Publish makes a web page with the crosstab and the records shown now.

The designer fills the whole screen: the configuration on the left, a preview on the right. Test on: the current result (as it was when the designer opened) or the own query; the main search does not change the preview. Toolbar: New crosstab; the list of crosstabs; the pen edits the record (name, owner, visibility); Save; Save as (a new crosstab with the Name of the form, "(copy)" added when the Name is not changed); Delete (refused while website pages use the crosstab); Help; Close.

  • Source: the name; the Query (its own records; ▾ copies the current result or a saved filter; it may have parameters); the Record type: the types of the test records with their number. Only records of this type are counted; its fields are offered.
  • Rows, Columns, Pages: the field (text, term, date, number or pointer field, also of the records they point to, up to two links; Alphabetic, the type filter and metadata in the field list); a caption; the values, as the type of the field allows: Each value, Dates by period (dates: years, decades, centuries — the default), Equal ranges (numbers — the default), or Own ranges (numbers, dates, terms): intervals (1900<>1909) and groups of terms with a label, made as the ranges of a thematic map (Add range, Generate ranges, Remove all). Values outside the ranges are other values; records without a value are (no value). Another field sets the values back to the default of its type.
  • Measure: count of records, or sum / average / minimum / maximum of a numeric field.
  • Display and default values: title, values, row and column percentages, totals, blank for zero, blank rows and columns, decimals; Table, Chart or both; the chart type (bars, stacked bars, horizontal bars, line, pie, doughnut).
  • Visitors on a website: what a visitor may change (view only; the display; also the fields and the measure, from the fields chosen here), the exports (CSV, Excel, PDF, chart image, print) and whether a click on a count shows its records in the other modules of the page.

Changes are shown in the preview at once and kept after Save. Above the table the display can be changed for a moment (values, percentages, totals, chart type, swap rows and columns). With more than 50 000 records the crosstab is counted after Update; Stop ends a long calculation.
